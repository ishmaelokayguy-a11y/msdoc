# Ограничения

[English](../en/limitations.md) · **Русский**

## Поддерживаемые форматы

| Вход | Результат |
|---|---|
| Word 97, 2000, XP, 2003 (`.doc`, `nFib ≥ 0x00C1`), в том числе сохранённые из Word 2007+ в режиме совместимости | поддерживается |
| Word 6/95 (`nFib < 0x00C1`), Word 2.0 и старше | `UnsupportedFormatError` |
| OLE-файл другой программы (`.xls`, `.ppt`, `.msg` и т. п.) | `UnsupportedFormatError` |
| Документ с паролем | `EncryptedDocumentError` (расшифровка не реализована) |
| `.rtf` (начинается с `{\rtf`) | читается парсером RTF, см. README |
| `.odt`, `.ods`, `.odp` (zip с `mimetype` OpenDocument) | читаются парсерами ODF, см. README |
| `.docx`, текст, любой другой не-OLE файл | `NotOleFileError` |
| Повреждённый `.doc` | `CorruptDocumentError`, либо частичный результат с записью в `Document.warnings` |

## Что именно извлекается

**Содержимое и структура:** текст шести историй, растровые и векторные картинки, а также структура основного
текста — заголовки, списки (с метками Word), таблицы (с объединёнными ячейками и вложенностью), гиперссылки,
сноски. Она отдаётся в `Document.blocks` и в Markdown (`msdoc.to_markdown`).

Не извлекается:

- **Оформление:** шрифты, размеры, цвета, выравнивание, отступы, жирный/курсив/подчёркивание, границы и заливка таблиц.
- **Автонумерация в плоском тексте:** в `doc.text` и `doc.stories` номера списков и сносок не попадают (цель — совпадение
  с LibreOffice). Метки списков есть в `Paragraph.list_number` и в Markdown, но вычисляются по правилам Word
  приближённо: для сложных многоуровневых и «рестартующих» списков возможны расхождения.
- **Встроенные OLE-объекты** (диаграммы Excel, формулы, вложенные документы) и их картинки-превью.
- **Метаданные:** автор, даты, свойства документа, теги (автор и дата могут встретиться в тексте как поля).
- **Макросы** (VBA) — не выполняются и не анализируются.
- **Отслеживаемые изменения и скрытый текст:** поведение выбиралось по ориентиру LibreOffice; для
  юридически значимых сценариев сверьте результат на ваших файлах.
- **Позиция картинки на странице** и обтекание — не возвращаются; для картинки известны вид
  (`inline`/`floating`), история, позиция якоря `cp` и абзац, в котором она стоит (заглушка в Markdown).
- **Порядок плавающих объектов:** текст надписей, примечаний и колонтитулов отдаётся в `doc.extra` / `extra=True`
  без гарантий порядка; в Markdown основного текста он не вставляется.

**Точность структуры** сверена с LibreOffice: около 94 % на dev и 86 % на отложенной выборке (см. [quality.md](quality.md)).
На сложных документах возможны ошибки в уровнях списков, объединённых ячейках и порядке надписей.

## Особенности результата

- Порядок абзацев в `headers`, `comments`, `textboxes` не гарантируется.
- Один и тот же колонтитул может присутствовать в списке несколько раз, если он используется
  в нескольких разделах.
- Векторные картинки (WMF/EMF/PICT) отдаются как есть; растеризация — за вами. Большинство мультимодальных
  моделей не принимает WMF/EMF; пример `examples/llm_messages.py` пропускает их и оставляет пометку в тексте.
- Таблицы в Markdown выводятся как HTML, а не как pipe-таблицы: иначе нельзя передать объединённые ячейки и вложенность.
- Текст берётся в том виде, в каком хранится в файле: символы, которые Word отображает специальными
  значками (например, неразрывный пробел, мягкий перенос), могут присутствовать как управляющие
  коды. При необходимости нормализуйте текст (`str.translate`, регулярные выражения).

## Эксплуатационные ограничения

- **Время и память не ограничиваются самой библиотекой.** Файл читается целиком в память; разбор —
  чистый Python. Для файлов из недоверенных источников ограничивайте процесс снаружи: таймаут,
  `ulimit -v`, контейнер. См. [deployment.md](deployment.md).
- **Скорость.** Чистый Python медленнее нативных реализаций; на типичных документах — доли секунды,
  на больших файлах с сотнями картинок — секунды. Для пакетов используйте процессы.

## Расхождения с LibreOffice

Эталоном при разработке служил LibreOffice, но не он один определяет «правильный» результат.
На намеренно испорченных файлах (фаззер-корпус `sw/qa/core/data/ww8/pass`) LibreOffice выдаёт то, что
сумел спасти из повреждённой структуры, и такой результат не является ориентиром: на них библиотека
гарантирует отсутствие падений и зависаний, а не совпадение текста. Подробности — в
[quality.md](quality.md) и в `docs/lo_disagreements.md`.
