# Развёртывание (в том числе в закрытом контуре)

[English](../en/deployment.md) · **Русский**

## Требования

- Python ≥ 3.9 (проверено на 3.9). Сторонних зависимостей **нет**.
- ОС любая (чистый Python): Linux, macOS, Windows.
- LibreOffice, Word и интернет на целевой машине **не нужны**.

## Перенос в закрытый контур

Вариант A — колесо (рекомендуется):

```bash
# на машине с интернетом / сборкой
python3 -m pip install build
python3 -m build                      # dist/msdoc-0.5.0-py3-none-any.whl и .tar.gz
sha256sum dist/*                      # запишите контрольные суммы

# в контуре
python3 -m pip install --no-index msdoc-0.5.0-py3-none-any.whl
python3 -c "import msdoc; print(msdoc.__version__)"
```

`--no-index` гарантирует, что `pip` не полезет в сеть. Так как зависимостей нет, больше ничего
переносить не нужно.

Вариант Б — просто каталог: скопируйте `src/msdoc/` рядом с вашим кодом или добавьте `src` в `PYTHONPATH`.
Это работает без установки.

Вариант В — исходники целиком (`git clone`/архив) вместе с `docs/` и `examples/`, если нужна
документация и пакетный скрипт.

## Проверка после установки

```python
import msdoc
print(msdoc.__version__)
text, media = msdoc.to_markdown("любой_ваш_файл.doc")
print(len(text), len(media), [m.mime for m in media])
print(text[:1000])
```

Рекомендуется прогнать 20–50 ваших реальных документов и убедиться, что результат вас устраивает
(особенно нумерацию списков, объединённые ячейки таблиц, скрытый текст — см. [limitations.md](limitations.md)); сравните
Markdown с тем, как документ выглядит в Word.

## Безопасность

`.doc` — формат со сложной структурой, а разбор входных файлов — классическая поверхность атаки.
Что делает библиотека: проверяет границы всех чтений, ограничивает циклы и рекурсию, не выполняет
макросы и вложенный код, не запускает внешние программы и не обращается к сети. Все ошибки
оформляются как `MsDocError`.

Что нужно делать вам, если файлы приходят извне:

1. Запускайте разбор в **отдельном процессе** с ограничениями (таймаут, память, права): библиотека
   не ограничивает время и память сама. Пример — `examples/extract_folder.py` (изоляция по
   `subprocess` с таймаутом).
2. Ограничивайте размер входного файла до разбора (`os.path.getsize`).
3. Ограничивайте память процесса (`ulimit -v`, cgroups, лимиты контейнера).
4. Не доверяйте извлечённому тексту при дальнейшей обработке (шаблонизаторы, SQL, командная строка):
   это недоверенные данные.
5. Картинки декодируйте и показывайте безопасными средствами (изображения тоже могут быть
   специально испорчены); `msdoc` их не интерпретирует, а лишь вырезает из контейнера.

## Ресурсы

- Время: чистый Python; обычный документ — доли секунды, объёмные — секунды.
- Память: файл читается целиком, плюс извлечённые картинки в памяти. Для больших пакетов обрабатывайте
  файлы по одному (или в пуле процессов) и не накапливайте `Document` в списке.
- Параллелизм: процессы, а не потоки (GIL).

## Лицензия при внутреннем использовании

Проект распространяется на условиях **MPL-2.0** (файловый copyleft), как и LibreOffice, часть логики
которого перенесена в код. Практически это значит:

- Использовать библиотеку внутри организации, в том числе в закрытых продуктах и сервисах, можно.
- Сохраняйте файлы `LICENSE` и `NOTICE`, а также заголовки в исходных файлах (в них указано, какие
  части перенесены из LibreOffice).
- Если вы изменяете **файлы библиотеки** и передаёте результат за пределы организации
  (распространяете), изменённые файлы нужно передавать под MPL-2.0 вместе с исходным кодом.
  Ваш собственный код, который лишь вызывает `msdoc`, этим не затрагивается.
- Тестовые документы и эталонные данные оракула в дистрибутив не входят.

Это техническое резюме, а не юридическая консультация: для окончательных выводов проконсультируйтесь
с юристом вашей организации.
