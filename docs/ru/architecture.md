# Архитектура

[English](../en/architecture.md) · **Русский**

Бинарный `.doc` (Word 97–2003) — это контейнер OLE2/CFB, внутри которого лежат несколько потоков.
Текст хранится отдельно от разметки, а разметка — отдельно от таблиц свойств. Библиотека проходит
по цепочке слоёв; каждый слой — отдельный модуль.

```
bytes ─► cfb.py ─► fib.py ─► pieces.py ─► props.py ─► stories.py ─► images.py ─► blocks.py ─► Document
         OLE2      заголовок  таблица      свойства    истории,      картинки     структура    │
         контейнер  FIB        кусков       символов    абзацы                     (заголовки,  ▼
                                                                                  списки,    markdown.py
                                                                                  таблицы)   ─► str
```

## Поток данных в `msdoc.extract`

1. **`cfb.CompoundFile(data)`** — разбирает контейнер OLE2 (MS-CFB): заголовок, FAT/miniFAT,
   каталог. Даёт `open_stream("WordDocument")`, `open_stream("1Table")`, `open_stream("Data")` и т. д.
2. **`fib.parse_fib(WordDocument)`** — File Information Block: версия (`nFib`), флаги (шифрование,
   `fWhichTblStm` — какой из потоков `0Table`/`1Table` использовать), длины историй (`ccpText`,
   `ccpFtn`, `ccpHdd`, …) и пары `(fc, lcb)` на все таблицы документа. Word 6/95 и зашифрованные файлы
   отсеиваются здесь.
3. **`pieces.PieceTable`** — таблица кусков (структура `Clx` в потоке таблиц). Она сопоставляет
   символьные позиции (CP) байтам в `WordDocument`: часть текста хранится «сжатым» (cp1252, 1 байт на
   символ), часть — как UTF-16LE. Даёт перевод CP ↔ FC и чтение текста по диапазону CP.
4. **`props.CharProps`** — свойства символов: страницы FKP для `CHPX` и последовательности `sprm`.
   Нужны, чтобы узнать, к какому символу относится картинка или специальный знак (например,
   `sprmCPicLocation`, признак «специального» символа).
5. **`stories.build_stories`** — собирает истории (основной текст, сноски, концевые сноски,
   колонтитулы, комментарии, надписи): режет единый поток CP по границам из FIB, обрабатывает
   специальные символы (`0x07` конец ячейки/строки, `0x13/0x14/0x15` метки полей, `0x01` картинка,
   `0x08` рисованный объект), поля (код против результата), таблицы. Возвращает истории и «якоря»
   для картинок.
6. **`images.extract_images`** — картинки. Два пути, общий декодер BLIP:
   - **строчные** (`0x01`): структура `PICF` в потоке `Data`, внутри — запись OfficeArt с BLIP;
   - **плавающие** (`0x08`): шаблон `OfficeArtContent` (`DggInfo`, контейнеры фигур, `FBSE`), BLIP либо
     лежит в потоке `WordDocument` по смещению (отложенный поток), либо встроен в `FBSE`.
   BLIP-метафайлы (WMF/EMF/PICT) хранятся сжатыми zlib и распаковываются. DIB превращается в BMP с
   добавлением заголовка.
7. **`blocks.build_blocks`** — строит `Document.blocks`, `notes` и `extra`: поверх плоских историй
   накладывает структуру. Заголовки — по стилю (`sti`) и `sprmPOutLvl`; списки — по `sprmPIlfo`/`sprmPIlvl`
   и таблицам `PlcfLst`/`PlfLfo` (включая вычисление метки «3.», «b)», «IV.»); таблицы — по глубине вложенности,
   `sprmPFTtp`/`sprmPFInnerTtp` и `sprmTDefTable` (объединение ячеек); места картинок и ссылок на сноски —
   символы `U+FFFC`/`U+E000` в тексте абзаца; гиперссылки — поля `HYPERLINK`. Структура всегда проверяется на
   совпадение с плоским текстом: при расхождении модуль откатывается к обычным абзацам, текст не теряется.
8. **`markdown.to_markdown`** — чистая функция над `Document`: рендерит блоки в Markdown, таблицы — в HTML.
9. **`api.extract`** — собирает всё в `Document`. Любая ошибка разбора превращается в подкласс
   `MsDocError`.

## Модули

| Модуль | Ответственность | Основные источники |
|---|---|---|
| `cfb.py` | контейнер OLE2 | [MS-CFB] |
| `fib.py` | FIB, версия, шифрование, указатели на таблицы | [MS-DOC] §2.5 |
| `pieces.py` | таблица кусков, CP↔FC | [MS-DOC] §2.9 `Clx`, `PlcPcd` |
| `props.py` | CHPX/FKP, sprm | [MS-DOC] §2.6, §2.9 |
| `stories.py` | истории, абзацы, поля, таблицы, спецсимволы | [MS-DOC] |
| `images.py` | строчные и плавающие картинки | [MS-DOC] `PICF`, [MS-ODRAW] |
| `blocks.py` | структура: заголовки, списки, таблицы, ссылки, сноски | [MS-DOC] `Lst`, `Lfo`, `TDefTable`, LibreOffice `ww8par*.cxx` |
| `markdown.py` | рендер блоков в Markdown (HTML для таблиц) | — |
| `model.py` | публичная модель данных | — |
| `errors.py` | иерархия исключений | — |
| `api.py` | точка входа: `extract`, `to_markdown` | — |

Часть алгоритмов перенесена из LibreOffice (`sw/source/filter/ww8/*`, `filter/source/msfilter/msdffimp.cxx`,
`sot/source/sdstor/*`); в заголовке файла указано, откуда именно.

## Принципы надёжности

Любой байт входного файла считается недоверенным:

- каждое чтение проверяется по границам потока;
- циклы и рекурсии ограничены размером данных (а не значениями из файла), циклы в цепочках FAT и в
  деревьях обнаруживаются;
- если структура повреждена, а текст ещё можно получить, библиотека пропускает повреждённый кусок и
  записывает причину в `Document.warnings`; фатальные случаи превращаются в `CorruptDocumentError`;
- наружу не выходят исключения, кроме `MsDocError`.

Эти свойства проверяются тестами на синтетических данных и прогоном по корпусу фазз-документов
(см. [development.md](development.md)).

## Что где лежит в файле (шпаргалка)

| Поток | Содержимое |
|---|---|
| `WordDocument` | FIB, текст (куски), FKP со свойствами; отложенные BLIP плавающих картинок |
| `0Table` / `1Table` | `Clx` (таблица кусков), PLCF границ абзацев/колонтитулов/сносок, OfficeArt-таблицы |
| `Data` | `PICF` и BLIP строчных картинок |
| `\x01CompObj`, `\x05SummaryInformation` и пр. | метаданные OLE (не используются) |
