# Качество: как измерялось и что получилось

[English](../en/quality.md) · **Русский**

Библиотека написана параллельными агентами Claude Code «с нуля» по спецификациям
[MS-DOC], [MS-ODRAW], [MS-CFB] и с чтением исходников LibreOffice. Её корректность проверялась
автоматически сравнением с LibreOffice на корпусе документов («оракул»).

## Корпус

| Источник | Что |
|---|---|
| тесты LibreOffice (`sw/qa/...`) | реальные и намеренно сложные документы, фаззер-корпус (`ww8/pass`, `ww8/fail`) |
| тестовые данные Apache POI | документы разных версий Word |

Всего 502 файла: `dev` (438; из них 341 обычных) и отложенная выборка `holdout` (64 обычных). Отложенная
выборка во время разработки была закрыта от агентов и использовалась только для итоговой проверки.

Не поддерживаемые форматы (Word 6/95, зашифрованные, не-OLE) входят в корпус отдельными категориями:
для них ожидается правильное исключение.

## Эталон

Каждый файл конвертируется в ODT утилитой LibreOffice (`soffice --headless --convert-to odt`),
а ODT разбирается скриптом, который собирает те же шесть историй и картинки. Эталон хранит текст по
историям и «отпечатки» картинок (sha256 и перцептивный хэш).

## Оценка файла (0…1)

```
score = 0.7 · сходство_текста + 0.3 · F1_картинок
```

- Сходство текста считается по историям (`main`, `footnotes`, `endnotes` — по порядку; `headers`,
  `comments`, `textboxes` — как наборы абзацев).
- F1 картинок: совпадение по sha256, затем по перцептивному хэшу; векторные картинки сопоставляются по
  количеству (LibreOffice перекодирует WMF в собственный формат).
- Файлы, которые не должны открываться (Word 6/95, шифрованные, не-OLE): 1 за правильное исключение.
- Фаззер-файлы и «битые»: 1, если нет падения и зависания.

**Храповик.** `baseline.json` хранит лучший достигнутый балл каждого файла. Любое изменение, снижающее
балл хоть одного файла, отклоняется (в том числе Stop-хуком у агентов). Поэтому качество в ходе
разработки не откатывалось назад.

## Результаты (версия 0.2.0, текст и картинки не менялись с 0.1.0)

| Выборка | Файлов | Средний балл | Текст | Картинки (F1) |
|---|---|---|---|---|
| dev, все категории | 438 | 0.9759 | 0.9777 | 0.9870 |
| dev, обычные документы без фаззер-файлов | 308 | — | **0.9926** | — |
| holdout (не видна агентам) | 64 | 0.9555 | 0.9364 | 0.9951 |
| holdout, обычные документы без фаззер-файлов | 55 | — | **0.9964** | — |

## Структура (Markdown)

Начиная с 0.2.0 отдельно оценивается структура основного текста (`struct`, 0…1): эталон строится из того же ODT
(заголовки и их уровни, элементы списков и тип списка, таблицы — число строк, столбцов и объединённых ячеек, места картинок,
число ссылок и сносок). Оценка не входит в общий балл, у неё свой храповик (`data/struct_baseline.json`).

| Выборка | Файлов | Структура |
|---|---|---|
| dev | 334 | 0.939 |
| holdout | 62 | 0.855 |

До реализации структуры (все абзацы обычные) было 0.47 на dev. Оценка проверяет типы и размеры, а не точный текст меток
нумерации и порядок надписей, поэтому она оптимистичнее, чем строгое побуквенное сравнение.

Вывод: на обычных документах совпадение текста с LibreOffice около 99 %, на отложенной выборке не хуже,
чем на dev — переобучения под корпус нет. Основная часть оставшихся потерь приходится на
фаззер-файлы, где эталон LibreOffice — это результат аварийного восстановления.

## Почему фаззер-файлы считаются отдельно

Каталог `sw/qa/core/data/ww8/pass` в LibreOffice содержит файлы, которые нашёл фаззер: они специально
испорчены, чтобы проверять, что LibreOffice **не падает**. Текст, который LibreOffice из них вытаскивает,
— побочный продукт восстановления и иногда выглядит как мусор (`1111…`) или обрывается. Попытка
совпасть с ним означала бы подгонку под чужие ошибки. Для таких файлов гарантия библиотеки — отсутствие
падений и зависаний. В отчёте оракула они выделены отдельной строкой.

Разобранные случаи (из отложенной выборки) показали три типа:

1. LibreOffice «схлопывает» таблицу или обрывает документ, а библиотека читает его полностью.
2. Структура настолько испорчена, что корректный результат — пустой или исключение.
3. Реальный текст документа, который LibreOffice по тем же причинам пропускает.

## Что не проверялось

- Сравнение с самим Word: эталон — LibreOffice, а не Word. Структура (особенно нумерация списков) в Word и LibreOffice может отображаться по-разному. В спорных местах LibreOffice может ошибаться.
- Большой корпус реальных документов из Word (например, Govdocs1): корпус состоит в основном из
  тестовых файлов LibreOffice и POI, поэтому на «живых» документах из вашей организации результат нужно
  проверить отдельно (см. [development.md](development.md), раздел «Добавить свои документы»).

## Как повторить измерение

```bash
python3 oracle/compare.py --quiet                       # dev
python3 oracle/compare.py --split holdout --quiet       # отложенная выборка
python3 oracle/compare.py --diff <id>                   # разница с LibreOffice по одному файлу (в том числе токены структуры)
```

Оценка текста использует `rapidfuzz`, если он установлен, иначе `difflib`; значения слегка различаются, поэтому
`--update-baseline` нужно запускать в том же окружении, где потом идёт проверка.

Нужны данные в `data/` (корпус и эталоны), они в пакет и репозиторий не входят.

## Excel (.xls) и PowerPoint (.ppt)

Та же идея оракула, что и для `.doc`, в `oracle/office_*.py`: `office_fetch.py` собирает корпус из файлов `qa`
LibreOffice и тестовых данных Apache POI (15 % — отложенная выборка), `office_golden.py` конвертирует каждый файл
LibreOffice в `.ods`/`.odp` и разбирает результат (показанный текст ячеек, объединённые диапазоны, тексты и заметки
слайдов, отпечатки картинок), `office_compare.py` сравнивает с ним msdoc:

```bash
python3 oracle/office_golden.py --ext xls --split dev        # возобновляемо, нужен soffice
python3 oracle/office_compare.py --ext xls                   # dev, reports/office-xls.md
python3 oracle/office_compare.py --ext ppt --diff <id>       # разница по слайдам/листам для одного файла
python3 oracle/office_compare.py --ext xls --check           # храповик против data/office/baseline-xls.json
python3 oracle/office_compare.py --ext ppt --split holdout   # итоговая оценка
```

Оценка = 0,7 × сходство текста + 0,3 × F1 по картинкам (текст xls — на каждый лист имя и по строке на ряд через
табуляцию; текст ppt — на каждый слайд абзацы, затем заметки). Файлы, которые нужно отвергнуть (зашифрованные, до 97-го,
не OLE), получают 1 при соответствующем `MsDocError`; падение, зависание или чужое исключение — 0.

| версия 0.4.0 | файлов | среднее | без падений |
|---|---|---|---|
| `.xls` dev | 641 | 0,974 | да |
| `.xls` holdout | 115 | 0,981 | да |
| `.ppt` dev | 190 | 0,957 | да |
| `.ppt` holdout | 26 | 0,969 | да |

Известные расхождения — поведение LibreOffice, а не дефекты: формулы, которые LibreOffice пересчитывает (показывает свой
результат или `Err:5xx`, где Excel сохранил значение), листы кеша сводных таблиц, поля с текущей датой, пустой слайд по
умолчанию для презентаций без слайдов и несколько файлов, где LibreOffice по-своему чинит повреждённую структуру.

## Rich Text Format (.rtf)

Корпус: файлы `.rtf` из `sw/qa` LibreOffice, Apache POI и Apache Tika (`oracle/office_fetch.py --ext rtf`),
605 файлов dev (532 обычных, 34 фаззер-файла, 23, которые LibreOffice отвергает, 16 не-RTF) и отложенная выборка.
Эталон — конвертация RTF -> ODT в LibreOffice, оценка тем же `oracle/compare.py --ext rtf`.

| выборка | значение |
|---|---|
| dev, средний балл (все виды) | 0,986 |
| dev, обычные файлы: балл / текст / картинки F1 / структура | 0,992 / 0,993 / 0,991 / 0,980 |
| падения, зависания | 0 |
| holdout, все виды / обычные файлы | 0,976 / 0,976 (103 / 86 файлов) |

Известные пробелы: LibreOffice рядом с каждой WMF/EMF-картинкой хранит запасной PNG (мы отдаём только векторную
картинку); поля, которые LibreOffice пересчитывает (DATE, номера страниц в теле многостраничных документов),
сохраняют результат из файла; объекты OLE вне таблиц не выдаются (LibreOffice встраивает их).


## OpenDocument (.odt, .ods, .odp): корпус и оракул

Корпус: файлы `.odt/.ods/.odp` (и шаблоны `.ott/.ots/.otp`) из LibreOffice core (`sw/qa`, `sc/qa`, `sd/qa`, xmloff,
chart2, vcl, ...), Apache Tika/POI, ODF Toolkit, odfdo, odfpy, ezodf и pandoc (`oracle/office_fetch.py --ext odf`),
без дубликатов, 15 % отложено, в `data/odf/` (раскладка, виды файлов и точные определения текста: `data/odf/README.md`).

Эталон нельзя строить по `content.xml` самого файла (его же читает парсер, получилась бы тавтология). LibreOffice
открывает каждый файл и (а) сохраняет его заново в том же формате; этот записанный LibreOffice ODF разбирается
существующими обходчиками и определяет оценку; (б) экспортирует его в простой текст / CSV: независимая перекрёстная
проверка, выводится как `plain`. Оценка = 0.7 × текст + 0.3 × F1 картинок; для `.odt` — определение историй как у
`.doc`/`.rtf` плюс оценка структуры, для `.ods`/`.odp` — построчные определения `.xls`/`.ppt` (`oracle/odf_score.py`).

```bash
python3 oracle/office_fetch.py --ext odf                 # корпус (можно перезапускать)
python3 oracle/make_golden.py --ext odt --budget 100     # эталон; повторять до "0 left" (также ods, odp)
python3 oracle/compare.py --ext ods --kind normal template
python3 oracle/compare.py --ext odp --diff <id>
python3 oracle/compare.py --ext odt --check              # храповик по data/odf/baseline-odt.json
python3 oracle/compare.py --ext odt --update-baseline    # завести базу, когда парсер появится
```

Результаты (версия 0.5.0; «обычные» — без фаззер-файлов, зашифрованных и отвергаемых):

| Формат | Выборка | Файлов | Среднее | Обычные файлы |
|---|---|---|---|---|
| `.odt` | dev | 1796 | 0,9967 | 0,9970 |
| `.odt` | holdout | 341 | 0,9959 | — |
| `.ods` | dev | 800 | 0,9894 | 0,9892 |
| `.ods` | holdout | 129 | 0,9759 | — |
| `.odp` | dev | 309 | 0,9950 | 0,9948 |
| `.odp` | holdout | 61 | 0,9999 | — |

Падений и таймаутов нет. Оценки ODF выше, чем у бинарных форматов, потому что ODF — родной формат LibreOffice.
Известные расхождения — поведение LibreOffice: формулы, которые он пересчитывает (RAND, TODAY, функции-надстройки),
поля даты, автора и имени файла, поля номера страницы, картинки, которые LibreOffice создаёт для связанных
объектов; см. `docs/lo_disagreements.md`.
